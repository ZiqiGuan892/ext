# AQA 训练分析：16+16 卡、BS=4、N=4、固定生成 10K

整理日期：2026-10-28。本文记录用户提供的配置 dump 摘要及 step 1–6 指标；统计基于已四舍五入的数据，没有重新运行训练。有效配置以 dump 为准，不以脚本默认值或先前环境变量代替。

**本组配置：全局 BS=4，每个 prompt 生成 N=4 条回复，每步共 16 条轨迹；长度预算为 2K prompt + 10K response = 12K。6 步平均 score 为 0.468，平均每步 2376.6 秒（39.61 分钟），端到端约 24.24 条轨迹/小时。**

¹ 轨迹/小时 = `16 ÷ step耗时 × 3600`，表示按当前 step 速率折算的产出；不是独立问题数。六步合并后为 **24.24 条轨迹/小时，约 0.00673 条/秒**。

所有 step 均有 `response_length/min=max=mean=10240`、`response_length/clip_ratio=1.0`、`response/aborted_ratio=0`。按日志长度口径，prompt + response 的每步均长为 **10317.5–10333.5**，六步平均 **10325.8**，并非 12288。

Prompt 长度来自训练数据中的长度字段或 attention mask 计数；音频特征、占位符和展开后的音频 token 需要另行核对。因此，这里的 77.5–93.5 不能直接用来判断 encoder 输出长度或推理引擎实际多模态上下文占用。

摘要另记录 `global_seqlen/minmax_diff=38`。固定的 response 长度也会缩小总长度差；仅凭这一差值，不能量化动态打包带来的收益。

### 吞吐量与耗时口径

verl 的 `perf/throughput` 定义为：

```text
perf/throughput = perf/total_num_tokens / timing_s/step / n_gpus
```

单位是 **token/s/卡，不是 samples/s**。本组数值与按 Actor16 + RM16 共 32 卡归一化吻合。例如 step 2：

```text
16 × (10240 + 93.5) / 2298.8 / 32 ≈ 2.2476 token/s/卡
```

这里用已舍入的 prompt 均长复算，只用于检查单位。按六步总 token 数和总耗时估算，整体约 **2.17 token/s/卡**；2.175 是六个日志值的算术平均，两者口径不同。

| 六步汇总 | 数值 |
|---|---:|
| 训练 prompt 采样次数 | 24 次（4 × 6；不保证跨 step 去重） |
| 总轨迹数 | 96 条 |
| 总 response token 数 | 983040 |
| 六步耗时之和 | 14259.6 秒，约 3.96 小时 |
| gen 耗时之和 | 13276.8 秒 |
| gen 占整步总耗时 | 93.11% |
| 每步非 gen 剩余耗时平均 | 163.8 秒 |

当前 V1 同步训练路径中，`timing_s/gen` 覆盖采样等待及采样结束处理；独立 GenRM 的结果在样本入队前完成，因此还包含判分和数据准备等待，不能直接当作纯 LLM 解码时间。`step - gen` 也不等于 Actor 反向训练时间；准确拆分需要 `timing_s/update_actor`、`old_log_prob`、`update_weights` 等原始指标。上述总耗时仅为六个 step 计时之和，不代表包含启动等开销的完整作业墙钟时间。

## 4. 本次结果说明

- **这是一组固定长输出负载的数据。** 10240 token 的生成下限和上限相同，且忽略 EOS；它适合记录长序列耗时，但不能代表允许自然结束时的吞吐或回答长度。采样阶段占比超过 93%，是当前总耗时的主要组成。
- **暂不能判断奖励改善趋势。** 评分范围为 0.250–0.802，只有 6 步、每步 4 个问题。当前 GenRM 实现支持覆盖率等连续分数；不能假设评分只能取 1/16 的整数倍，也不能仅根据六步波动称其为“纯噪声”。
- **低熵和较小 loss 需要结合回答内容及后续验证判断。** entropy 为 0.263–0.311，但这本身不证明重复退化、探索塌缩或学习停止。GSPO 使用长度归一化的序列概率比；不能仅与 token 级 PPO 的裁剪阈值比较，就断定 3e-4/4e-4 配错。
- **低 KL 支持当前采样上的 logprob 较接近，不证明整条精度链路无误。** 两端共享同一组错误权重时仍可能接近；音频 embedding、权重同步及实际答案质量需要各自的对照结果。
- **显存瓶颈尚未量化。** FP32 参数和 full precision 配置值得记录，但缺少本次峰值显存及阶段拆分，不能认定参数精度是唯一或最大来源，也不能直接将 rollout 显存比例从 0.5 提到 0.85。

配置、指标和计算口径可作为后续改变 BS、N、长度、精度模式时的对照基线；本次没有其他配置组的实测结果。

以下保留原命令。它仍继承脚本、环境及其他覆盖项；例如摘要中的最终 `gpu_memory_utilization=0.5` 覆盖项未出现在此片段中，复现时需同时保留有效配置 dump。

```bash
HUANYU_SKIP_EDITABLE_INSTALL=1 \

bash "$PROJECT_ROOT/examples/qwen3_6_huanyu/run_huanyu_aqa_audio_train.sh" \
  actor_rollout_ref.rollout.response_length=10240 \
  actor_rollout_ref.rollout.ignore_eos=true \
  ++actor_rollout_ref.rollout.engine_kwargs.q36_sampling.min_tokens=10240 \
  actor_rollout_ref.actor.use_dynamic_bsz=true \
  actor_rollout_ref.actor.ppo_micro_batch_size_per_gpu=1 \
  actor_rollout_ref.rollout.log_prob_use_dynamic_bsz=true \
  actor_rollout_ref.rollout.log_prob_micro_batch_size_per_gpu=1 \
  actor_rollout_ref.ref.log_prob_use_dynamic_bsz=true \
  actor_rollout_ref.ref.log_prob_micro_batch_size_per_gpu=1 \
  ++actor_rollout_ref.model.override_config.huanyu_sync_each_microbatch=false \
  actor_rollout_ref.model.override_config.attn_implementation=sdpa \
  actor_rollout_ref.rollout.max_num_seqs=32
```

口径核查依据：本地 verl 的 `verl/trainer/ppo/metric_utils.py`（吞吐、长度、score/reward）、`verl/trainer/ppo/v1/trainer_base.py`（阶段计时和资源计数）、`verl/trainer/ppo/core_algos.py::compute_policy_loss_gspo`（GSPO 概率比与裁剪），以及扩展中的 `verl_omni_ext/reward/genrm_verifier.py`（GenRM 评分）。
